# intentcall_webmcp — Design FAQ

**Q: Why separate from `intentcall_mcp`?**
A: WebMCP registers tools in the browser via `document.modelContext` with a different lifecycle than request/response MCP. Mixing both in one adapter would blur failure modes and hot-sync rules.

**Q: What happens when a web tool fails?**
A: In the generated bootstrap, failed execution rejects the `execute` promise. `WebMcpPublishAdapter` resolves `execute` with an `ok: false` result map instead. Missing `modelContext` is a registration report, not silent success ([ADR 0027](../../../docs/decisions/0027-agent-usable-projection-results.md)).

**Q: Does WebMCP replace MCP for IDE agents?**
A: No. WebMCP targets in-page agents; IDE and CLI agents still use `intentcall_mcp`.
